# Endpoint identity

AuthSurface freezes multi-method representation as method-specific records. A route endpoint with methods `POST, GET` becomes two records: one for the normalized route plus `GET`, and one for the normalized route plus `POST`. Methods are uppercased with invariant culture and sorted ordinally before records are emitted.

The durable identity is `case-folded normalized route pattern + HTTP method`. AuthSurface preserves the normalized route's original casing in the readable record, but the identity key uppercases the complete normalized pattern with invariant culture and uppercases the method. This makes route literals, parameter names, and any other pattern text that differs only by case resolve to one deterministic identity independent of source casing. Display names, controller/action names, source locations, endpoint order, and generated display text are never baseline keys. The readable route is normalized to an absolute pattern with one leading slash, collapsed duplicate separators, and no trailing slash except for `/`.

Two runtime route endpoints whose case-folded identities match are ambiguous. Scanning fails with the structured `duplicate-endpoint-identity` analysis error rather than silently selecting one endpoint. Endpoint exclusions are explicit and happen before identity validation. Routes that remain different after this rule, such as `/alpha` and `/beta`, retain separate records.
